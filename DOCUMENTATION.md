# VPN Manager Documentation

## 1. Новая архитектура VPN Manager

### Обновленная архитектура

#### Основные изменения:

1. **Client (VPN клиент)** - основная сущность вместо User
   - Имя, email, telegram_id
   - Может иметь несколько подписок
   - Управляется через меню "👤 Управление клиентами"

2. **Subscription (подписка)** - подписка клиента
   - Привязана к конкретному клиенту
   - Имеет уникальный токен
   - Может включать несколько inbound подключений
   - Настройки трафика и срока действия

3. **InboundConnection (подключение)** - уникальное подключение к inbound
   - Привязано к подписке и конкретному inbound
   - Создает клиента на 3x-ui панели
   - Уникальность: один inbound не может повторяться в одной подписке

4. **Inbound** - хранит информацию о клиентах
   - `client_count` - количество клиентов на inbound
   - Можно просматривать статистику клиентов

## 2. Поиск клиентов

### 2.1 Комплексный поиск клиентов

#### Обзор
Комплексный поиск ищет клиента **одновременно** по всем полям с логикой OR. Это значит, что если запрос совпадает с любым полем, клиент будет найден.

#### Логика работы
Комплексный поиск проверяет следующие поля одновременно:
- **Имя клиента** (с поддержкой нескольких слов)
- **Email клиента**
- **Telegram ID** (если запрос - число)
- **XUI email** (email из inbound подключений)

Используется логика OR - клиент найден, если совпадает **хотя бы одно** поле:
```sql
WHERE
    LOWER(name) LIKE LOWER('%query%')
    OR
    LOWER(email) LIKE LOWER('%query%')
    OR
    telegram_id = query
    OR
    LOWER(inbound_connections.email) LIKE LOWER('%query%')
```

#### Примеры использования комплексного поиска

**Пример 1: Поиск по части имени**
```text
Ввод: "ден"
Результаты:
✅ Найдет "Денис Петров" (имя содержит "ден")
✅ Найдет "Александр Денисов" (имя содержит "ден")
✅ Найдет "Денис" (точное совпадение)
✅ Найдет "Ольга Денисова" (имя содержит "ден")
```

**Пример 2: Поиск по части email**
```text
Ввод: "денис"
Результаты:
✅ Найдет клиента с email "денис@example.com"
✅ Найдет клиента с email "alex.denisov@vpn.com"
✅ Найдет клиента с email "test@денис.com"
✅ Найдет клиента с XUI email "денис@vpn.com"
```

**Пример 3: Поиск по Telegram ID**
```text
Ввод: "123456789"
Результаты:
✅ Найдет клиента с Telegram ID 123456789
✅ Найдет клиента с именем, содержащим "123456789" (если такой есть)
✅ Найдет клиента с email, содержащим "123456789"
```

**Пример 4: Сложный кейс - имя и email совпадают**
```text
Клиент:
- Имя: "Денис Петров"
- Email: "денис@vpn.com"
- Telegram ID: 123456789

Ввод: "ден"
Результаты:
✅ Найдет по имени: "Денис" содержится в "Денис Петров"
✅ Найдет по email: "ден" содержится в "денис@vpn.com"
```

**Пример 5: Многословный поиск по имени**
```text
Ввод: "денис петров"
Результаты:
✅ Найдет "Денис Петров" (любое слово совпадает)
✅ Найдет "Петров Денис" (любое слово совпадает)
✅ Найдет "Денисов Петр" (слово "денис" совпадает)
✅ Найдет "Иван Петров" (слово "петров" совпадает)
✅ Найдет "Денис" (один из параметров - полное совпадение)
✅ Найдет "Петров" (один из параметров - полное совпадение)
```

**Пример 6: Поиск по домену email**
```text
Ввод: "vpn.com"
Результаты:
✅ Найдет клиента с email "денис@vpn.com"
✅ Найдет клиента с email "ivan@vpn.com"
✅ Найдет клиента с XUI email "client@vpn.com"
```

#### Особенности

- **Многословный поиск по имени:** При вводе нескольких слов поиск ищет любое слово отдельно и полную фразу.
- **Telegram ID:** Если запрос - только цифры, то дополнительно ищется по Telegram ID.
- **Нормализация текста:**
  - Удаляются лишние пробелы.
  - Удаляются спецсимволы (кроме @ и . для email).
  - Слова короче 2 символов игнорируются (для многословного поиска).
- **JOIN для XUI email:** Поиск по XUI email требует JOIN с таблицей `inbound_connections`.

#### Преимущества комплексного поиска
1. **Максимальный охват**: Находит клиентов по любому доступному полю.
2. **Интуитивность**: Пользователю не нужно думать, по какому полю искать.
3. **Гибкость**: Работает с частичными совпадениями.
4. **Многословность**: Поддерживает поиск по нескольким словам в имени.
5. **Универсальность**: Одна строка поиска для всех типов данных.

#### Когда использовать
✅ **Идеально для:**
- Когда не уверены, по какому полю искать.
- Когда нужно найти клиента по минимальной информации.
- Когда нужна максимальная гибкость поиска.
- Когда клиенты могут иметь похожие данные в разных полях.

❌ **Не рекомендуется для:**
- Точного поиска по Telegram ID (лучше использовать отдельный поиск).
- Поиска конкретного email (лучше использовать отдельный поиск).
- Когда нужно сузить результаты (лучше использовать поиск по конкретному полю).

### 2.2 Примеры умного поиска клиентов

Умный поиск автоматически обрабатывает регистр, пробелы и спецсимволы, что делает поиск более удобным и прощающим ошибки пользователя.

#### Поиск по имени

**Базовый поиск:**
```text
иван
```
Найдет: "Иван Петров", "Иванов", "Максим Иванин", "Ivan"

**Поиск по нескольким словам:**
```text
иван петров
```
Найдет: "Иван Петров", "Петров Иван", "Петров Иван Сергеевич"

**С лишними пробелами:**
```text
иван   петров
```
Автоматически нормализуется в: "иван петров"

**Со спецсимволами:**
```text
иван,петров!
```
Найдет: "Иван Петров", "Петров Иван" (знаки препинания удалены)

**Смешанный регистр:**
```text
ИВАН ПЕТРОВ
```
Найдет: "Иван Петров", "иван петров", "ИВАН ПЕТРОВ" (без учета регистра)

#### Поиск по email

**Частичный email:**
```text
test
```
Найдет: "test@example.com", "mytest@domain.com", "testing@vpn.com"

**Домен:**
```text
@example.com
```
Найдет: все email с доменом "example.com"

**С лишними пробелами:**
```text
  test@example.com
```
Автоматически нормализуется в: "test@example.com"

**В разном регистре:**
```text
TEST@EXAMPLE.COM
```
Найдет: "test@example.com", "TEST@example.com", "test@EXAMPLE.COM" (приводится к lowercase)

#### Поиск по Telegram ID

**Точное совпадение:**
```text
123456789
```
Найдет: клиента с Telegram ID 123456789

**С пробелами (автоочистка):**
```text
  123456789
```
Найдет: клиента с Telegram ID 123456789

**С буквами (ошибка):**
```text
12345abc
```
Ошибка: "Telegram ID должен быть числом"

#### Сценарии использования

- **Сценарий 1: Не помните точное имя** - Ввод `иван` найдет всех клиентов с "иван" в имени.
- **Сценарий 2: Неверный регистр** - Ввод `ИВАН ПЕТРОВ` найдет "Иван Петров" (регистр игнорируется).
- **Сценарий 3: Лишние пробелы** - Ввод `иван    петров` автоматически удалит лишние пробелы.
- **Сценарий 4: Поиск по VPN email** - Ввод `vpn-client@example.com` найдет клиента, у которого есть VPN email, содержащий этот адрес.
- **Сценарий 5: Поиск по домену email** - Ввод `@example.com` найдет всех клиентов с email из домена example.com.
- **Сценарий 6: Поиск по любому из слов** - Ввод `петров иван сергеевич` найдет любого клиента, у которого есть любое из этих слов в имени.

#### Советы по поиску

✅ **Лучшие практики:**
- Используйте минимальную уникальную часть имени.
- Для email можно использовать домен для группового поиска.
- Для Telegram ID используйте только цифры.
- Не бойтесь лишних пробелов и спецсимволов.

❌ **Чего избегать:**
- Слишком короткие запросы (менее 2 символов).
- Поиск Telegram ID с буквами.
- Слишком общие запросы (например, "а") - найдет слишком много результатов.

## 3. Множественный выбор Inbounds

### Описание
Функционал позволяет включать и отключать несколько inbounds в подписке одновременно.

### Использование

#### Вход в режим множественного выбора
1. Перейдите в подписку: `Управление клиентами` → выбрать клиента → выбрать подписку → `Inbounds`
2. Нажмите кнопку `✅ Множественный выбор`

#### Режим множественного выбора
- Каждый inbound показывается с чекбоксом (✅ - выбран, ⭕ - не выбран)
- Статус подключения показывается цветом: 🟢 - включен, 🔴 - отключен
- Отображается счетчик выбранных inbounds

#### Действия с выбранными inbounds
- **✅ Включить выбранные** - включает все выбранные inbounds
- **❌ Отключить выбранные** - отключает все выбранные inbounds
- **🔙 Выход** - возвращает к обычному списку inbounds

#### Подтверждение действий
После выбора действия требуется подтверждение:
- **✅ Подтвердить** - выполнить выбранное действие
- **❌ Отмена** - вернуться к выбору inbounds

### Техническая реализация

**Состояния FSM:**
- `SubscriptionManagement.inbounds_multi_select_mode` - режим выбора inbounds
- `SubscriptionManagement.inbounds_multi_confirm_action` - подтверждение действия

**Callback data:**
- `inbounds_multi_select_{subscription_id}` - вход в режим мультивыбора
- `multi_select_conn_{connection_id}` - выбор/снятие выбора подключения
- `multi_select_enable_all` - включить выбранные
- `multi_select_disable_all` - отключить выбранные
- `multi_select_confirm` - подтвердить действие
- `multi_select_cancel` - отмена/выход

**Клавиатуры:**
- `get_multi_select_keyboard(connections, selected_ids)` - клавиатура с чекбоксами
- `get_multi_select_confirm_keyboard()` - клавиатура подтверждения действия

## 4. Синхронизация данных

### Обзор
Система синхронизации обеспечивает консистентность данных между базой данных бота и панелями 3x-ui.

### Архитектура

**Стратегии синхронизации:**
- **Оптимистичные обновления (Optimistic Updates)**: Запись в БД, потом в XUI с rollback при ошибках.
- **Read-Only Cache**: Сервера и inbounds как кэш из XUI.
- **Двусторонняя синхронизация**: Подключения с проверкой новизны данных.

**Статусы синхронизации:**
- `synced`: Данные синхронизированы
- `pending`: Синхронизация в процессе
- `error`: Ошибка при синхронизации
- `offline`: Сервер недоступен

### Использование

**Автоматическая синхронизация:**
```python
from app.services.sync_service import SyncService

sync_service = SyncService(session)
await sync_service.start_background_sync()
```

**Ручная синхронизация:**
```python
from app.services import SyncService

sync_service = SyncService(session)
results = await sync_service.manual_sync("server")
# results: {"synced": 5, "errors": 0, "details": []}
```

### Интеграция с ботом

**Команды синхронизации:**
- `🔄 Синхронизировать все` - Полная синхронизация
- `🖥️ Синхронизировать сервера` - Синхронизация только серверов
- `📊 Проверить целостность` - Проверка целостности данных

**Триггеры синхронизации:**
Синхронизация автоматически запускается:
- При изменении данных в боте
- Каждые 5 минут (фоновая задача)
- При запуске бота

### Мониторинг

**Логи:**
Синхронизация пишет подробные логи:
```text
🔄 Начало цикла синхронизации в 2024-03-24 16:00:00
✅ Сервер 1 синхронизирован
📊 Статистика целостности: {'total': 10, 'synced': 8, 'error': 2}
✅ Цикл синхронизации завершен за 2.34s
```

**Статусы серверов:**
В админском меню можно видеть статусы:
- ✅ Синхронизирован
- ⚠️ Ошибка синхронизации
- 🔴 Недоступен

### Troubleshooting

**Сервера не синхронизируются:**
1. Проверьте статус сервера: `sync_status == "offline"`
2. Проверьте соединение с сервером
3. Посмотрите логи ошибок: `sync_error`

**Расхождения данных:**
1. Запустите полную синхронизацию
2. Проверьте целостность данных
3. При необходимости удалите проблемные записи

## 5. Разработка и тестирование

### 5.1 Руководство по тестированию

В этом проекте используются [pytest](https://docs.pytest.org/) и [pytest-asyncio](https://pytest-asyncio.readthedocs.io/) для тестирования.

#### Настройка
Установите зависимости для тестирования:
```bash
pip install -e ".[dev]"
```

#### Запуск тестов
- Все тесты: `pytest`
- С подробным выводом: `pytest -v`
- Конкретный файл: `pytest tests/test_utils.py`
- Конкретный тест: `pytest tests/test_utils.py::test_generate_uuid`
- С покрытием кода: `pytest --cov=app --cov-report=html`

#### Структура тестов
```text
tests/
├── conftest.py           # Конфигурация и фикстуры pytest
├── test_config.py         # Тесты конфигурации
├── test_utils.py          # Тесты утилит
├── test_services.py        # Тесты слоя сервисов
└── test_models.py         # Тесты моделей базы данных
```

#### Фикстуры
Файл `conftest.py` предоставляет следующие фикстуры:
- `test_engine`: Движок базы данных в памяти
- `test_session`: Асинхронная сессия базы данных
- `mock_settings`: Мок объекта настроек
- `event_loop`: Асинхронный цикл событий для тестов

#### CI/CD
Тесты должны запускаться автоматически при push/PR.
```yaml
name: Тесты
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - uses: actions/setup-python@v2
        with:
          python-version: '3.11'
      - run: pip install -e ".[dev]"
      - run: pytest
```

#### Цели покрытия кода
- Стремитесь к покрытию >80% кода
- Фокусируйтесь на критических путях (services, utils)
- Обработчики UI/бота имеют меньший приоритет, но должны тестироваться

### 5.2 Миграции базы данных

В проекте используется [Alembic](https://alembic.sqlalchemy.org/) для миграций базы данных.

#### Настройка
После клонирования репозитория инициализируйте Alembic (если еще не инициализирован):
```bash
alembic init alembic
```

#### Выполнение миграций

**Создание новой миграции:**
После изменения моделей создайте новую миграцию:
```bash
alembic revision --autogenerate -m "Описание изменений"
```

**Применение миграций:**
Примените ожидающие миграции к базе данных:
```bash
alembic upgrade head
```

**Откат миграций:**
- На один шаг назад: `alembic downgrade -1`
- К конкретной миграции: `alembic downgrade <revision_id>`

**Просмотр истории и текущей ревизии:**
```bash
alembic history
alembic current
```

#### Офлайн режим
Для генерации SQL без подключения к базе данных:
```bash
alembic upgrade head --sql
```

#### Важные заметки
1. **Всегда проверяйте сгенерированные миграции** - `--autogenerate` полезен, но не идеален.

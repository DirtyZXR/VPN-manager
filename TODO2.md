## 🚨 КРИТИЧЕСКИЕ БАГИ И АУДИТ БЕЗОПАСНОСТИ

### 1. Проблемы с сессиями и утечки памяти
- **Утечка сессий (aiohttp) в меню пользователя**: В `show_subscription_status` скрипт открывает сессии XUI, но при ошибках Telegram API (`MessageNotModified` и т.д.) они не закрываются из-за отсутствия блока `finally`. Обязательно нужно использовать `try...finally` или `async with`.
- **Утечка памяти в кэшировании XUI клиентов**: Кеш `_xui_clients` может расти бесконечно без механизма очистки. Необходимо внедрить LRU Cache.
- **Утечка сессий БД в async контексте**: Множественные `async_session_factory()` в одном обработчике без очистки приводят к исчерпанию пула (например, `app/bot/handlers/admin/subscriptions.py`).

### 2. Транзакции и целостность базы данных
- **Бомба замедленного действия (DetachedInstanceError)**: В `AuthMiddleware` сессия БД закрывается до передачи `client` в хендлеры. Если использовать ленивую загрузку свойств `client`, бот упадет. **Решение**: Миграция всех хендлеров на паттерн `session-per-request` (передавать открытую `db_session` из middleware).
- **Race Condition при генерации токенов**: Токены создаются без проверки уникальности с обработкой `IntegrityError` (нужен retry-механизм в `generate_subscription_token`).
- **Отсутствие отката транзакций (XUI)**: В `new_subscription_service.py` при ошибке XUI API используется ручной `rollback()` без `begin_nested()`, что может оставить БД в несогласованном состоянии.
- **Deadlock при конкурентных обновлениях**: Обновление XUI клиентов без согласованной блокировки. Нужна сортировка объектов перед апдейтом.
- **Риск SQL-инъекции в поиске**: Использование `text()` с пользовательским вводом в `client_service.py`. Заменить на `func.lower(Client.name).like(...)`.

### 3. Баги Telegram API (Таймауты и Лимиты)
- **TelegramBadRequest: query is too old**: Возникает при долгих SSH/API операциях (добавление клиентов, синхронизация серверов) из-за 30-секундного таймаута callback-запросов. **Решение**: Ранний вызов `callback.answer("🔄 Начинаю...", show_alert=False)` перед долгой задачей, а результат отправлять через `message.answer()` или `edit_text()`.
- **MESSAGE_TOO_LONG**: Вызов `callback.answer(..., show_alert=True)` с длинными ошибками SSH-команд. Нужно обрезать текст до 190 символов.

### 4. Ошибки синхронизации и логики (Sync Service)
- **Односторонняя синхронизация (Потеря данных)**: SyncService работает только в режиме Pull. Если панель была недоступна при смене лимитов в боте, новые настройки в БД перетрутся старыми из панели при следующем фоновом запуске. **Решение**: Добавить Push-синхронизацию для записей со статусом `pending` / `error`.
- **Осиротевшие подключения**: При сбоях панели, созданные inbounds зависают со статусом `error` и никогда больше не отправляются в панель.
- **Синхронизация удаленных inbounds**: Если Inbound удален в XUI, бот спамит ошибками `record not found`. Нужно помечать такие inbounds как `is_active=False`.
- **Greenlet_spawn error**: При вызове DB-операций в синхронном контексте (во время создания AWG/XUI клиентов, функция `_get_connection_traffic`).
- **Несогласованные часовые пояса**: Разница между `datetime.now()` (naive) в `InboundConnection` и `datetime.now(timezone.utc)` (aware) в `Subscription`.

## 📦 ИНСТАЛЛЕРЫ И VPN ПРОВОДНИКИ (Прямое SSH-управление)

**Концепт**: Полный отказ от PHP-панели. Управление серверами, установка Docker, настройка протоколов (XUI, AWG, MTProxy) осуществляется напрямую через `asyncssh`.

### Инсталлеры (InstallerService)
- **BaseInstaller**: `_prepare_server()` (Установка UFW, Docker, sqlite3, базовых утилит).
- **AWGInstaller**: Выделение UDP порта, генерация ключей сервера, создание `awg0.conf`, запуск `amneziavpn/amnezia-wg`.
- **MTProxyInstaller**: Выделение TCP порта, генерация `secrets.txt`, запуск контейнера.
- **XUIInstaller**: Выбор портов, путей. Установка `3x-ui` (host network), SQL инъекции в `x-ui.db` для первичной настройки (пароли/пути), рестарт контейнера.

### Управление протоколами (VPN Providers)
Все провайдеры реализуют интерфейс `BaseVPNProvider`.
1. **AmneziaAWGProvider**:
   - *Добавление*: Генерация ключей клиента, поиск свободного IP (парсинг `awg0.conf`), запись `[Peer]` в конфиг, горячая синхронизация `awg syncconf awg0 ...`. Локальная генерация `.conf` файла для Telegram.
   - *Удаление*: `awg set awg0 peer <public_key> remove`, и удаление блока из `awg0.conf`.
2. **MTProxyProvider**:
   - Добавление/удаление секретов через редактирование `config.json` по SSH, с последующим мягким рестартом `docker restart mtproxy`.
3. **XUIProvider**: Унифицированная обертка текущего API 3x-ui.

## 📚 АРХИТЕКТУРА И ПАТТЕРНЫ (Architecture Analysis)

### Иерархия Данных (Models)
```text
Client (Реальный юзер)
  └── Subscription (Группа подписок с общим token)
        └── InboundConnection (Конкретное подключение, UUID/email)
              └── Inbound (Конфиг панели, VLESS/AWG/etc)
                    └── Server (VPS с панелью/SSH)
```
- **Subscription Token** привязан к (Client + Server). 
- URL подписки: `https://{host}/{urlsub}/{token}`.

### Паттерны БД и Сессий
- **Eager Loading**: Использовать `selectinload()` для всех вложенных структур, чтобы избежать N+1 запросов.
- **Транзакции**: Сервисный слой делает `session.flush()` для получения ID, а хендлеры (или контекстный менеджер) делают финальный `session.commit()`.
- **Кеширование**: `XUIClient` кешируется в памяти сервиса (с валидацией cookie). Inbounds кешируются в SQLite (таблица `inbounds`).

### Синхронизация (SyncService)
- Происходит раз в 5 минут (фоновая задача с `asyncio.Lock()`).
- Включает 3 фазы: синхронизация серверов, синхронизация трафика клиентов, проверка целостности.

### Безопасность
- Пароли серверов шифруются алгоритмом **Fernet**. Обязательная дешифрация в рантайме.
- Проверки авторизации в Middleware.
- Все диалоги построены через FSM (`aiogram.fsm`). Обработчики отмены `/cancel` обязательны.
